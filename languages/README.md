# Zentranslate translation packs

This directory holds the translation files for the **plugin's own UI**
(admin pages, profile fields, settings labels, etc.). Translators turn
the source `.pot` into per-locale `.po` files, then compile them to
`.mo` for PHP and `.json` for the React admin.

## Files

| File pattern | Purpose | Generated by |
|---|---|---|
| `zentranslate.pot` | Source catalog — all extracted strings. **Do not edit by hand.** | `wp i18n make-pot` |
| `zentranslate-{locale}.po` | Per-locale translations. Translators edit this. | Poedit / WP-CLI |
| `zentranslate-{locale}.mo` | Compiled binary for PHP `__()`. | Poedit on save / `msgfmt` |
| `zentranslate-{locale}-{script-handle}.json` | React admin translations for `wp_set_script_translations`. | `wp i18n make-json` |

Examples for Spanish (Spain):

```
zentranslate-es_ES.po
zentranslate-es_ES.mo
zentranslate-es_ES-zentranslate-backend.json
```

## Workflow

### 1. Regenerate the .pot (when source strings change)

Run from the plugin root:

```bash
wp i18n make-pot . languages/zentranslate.pot \
  --domain=zentranslate \
  --exclude=node_modules,assets/build \
  --skip-audit
```

### 2. Update a translation

Open `languages/zentranslate.pot` in [Poedit](https://poedit.net/),
choose "Create new translation from POT". After translating, Poedit
writes both the `.po` and `.mo` files.

CLI alternative:

```bash
cp languages/zentranslate.pot languages/zentranslate-es_ES.po
# … edit translations in the .po …
msgfmt languages/zentranslate-es_ES.po -o languages/zentranslate-es_ES.mo
```

### 3. Build JSON files for the React admin

The React admin reads translations via `wp_set_script_translations`,
which needs a per-script JSON file:

```bash
wp i18n make-json languages/ --no-purge
```

This walks every `.po` file, extracts strings used by JS files (it
inspects the source map to know which file used each string), and
writes one JSON per script handle. Output filename pattern:

```
zentranslate-{locale}-{md5(script-relative-path)}.json
```

`wp i18n make-json` figures the md5 part out automatically — don't
fabricate it.

### 4. Drop the files in `languages/` and reload

Once the `.mo` and `.json` files are in this directory, switching
admin language via the admin bar or user profile activates them
immediately.

## How runtime loading works

- **PHP side**: `load_plugin_textdomain('zentranslate', false, '.../languages/')`
  is wired in [includes/hooks.php](../includes/hooks.php). It reads `.mo`
  files for the active locale.
- **React side**: [includes/assets.php](../includes/assets.php) calls
  `wp_set_script_translations('zentranslate-backend', 'zentranslate', '.../languages/')`.
  WordPress loads the matching `-{locale}-{handle}.json` automatically.
- **Locale selection**: [includes/admin/localizer.php](../includes/admin/localizer.php)
  filters the WordPress `locale` in admin to the current user's
  `ztrans_preferred_language` meta. Frontend keeps its URL-derived
  language.
